# ТЗ: хостинг учебных проектов

Oct 30, 2026, @Sergey Belousov

## Цель и рамки

Нужен один сервер, на котором ученики публикуют свои учебные сайты и Telegram-ботов. Учитель один раз создаёт проект ученика, а дальше каждое обновление кода в репозитории само выкладывается на сервер в течение пары минут.

В работу входит:

- аренда VPS у российского провайдера и покупка домена в зоне .ru;
- установка панели Coolify, которая собирает и запускает проекты;
- шаблоны репозиториев для сайта и для бота, а также страница-витрина с работами учеников на главном домене;
- бэкапы, уведомления о сбоях и короткие инструкции для учителя и ученика.

В работу не входит:

- базы данных общего пользования и хранилище файлов для учеников;
- личные кабинеты, оплата и любая учётная система школы;
- доступ учеников к панели управления.

## Роли

У системы три роли, и доступ к серверу есть только у администратора. Администрирует Сергей удалённо из Еревана, через Claude Code по SSH-ключу.

| Роль | Что делает | Доступ |
| --- | --- | --- |
| Администратор | Настраивает сервер и Coolify, обновляет их, следит за бэкапами | SSH по ключу, панель Coolify с правами владельца, личный кабинет провайдера |
| Учитель | Создаёт репозитории и проекты учеников, смотрит логи, вписывает токены ботов | Панель Coolify, права администратора организации школы в Forgejo |
| Ученик | Пишет код и отправляет его в свой репозиторий | Только свой репозиторий, в панель не заходит |

Учеников не пускают в панель, потому что права в Coolify задаются на команду целиком, и ученик сможет изменить или удалить чужие проекты.

## Сценарии

Ученик после первой настройки только отправляет код в репозиторий, всё остальное делают учитель и сервер.

### Новый проект ученика

1. Учитель заводит ученику аккаунт в Forgejo, создаёт репозиторий из шаблона в организации школы и даёт ученику право записи.
2. В Coolify учитель создаёт приложение из этого репозитория и задаёт поддомен вида `vasya.<домен>`. Для бота вместо поддомена вписывается токен в переменную `BOT_TOKEN`.
3. Учитель запускает первую сборку и проверяет, что сайт открывается или бот отвечает.

Цель по времени: не больше 5 минут на одного ученика по инструкции для учителя.

### Обновление проекта

1. Ученик отправляет код в ветку `main` из VS Code или загружает файлы через веб-интерфейс Forgejo.
2. Forgejo через вебхук сообщает Coolify о новом коммите, и Coolify собирает новую версию.
3. Если сборка прошла, новая версия заменяет старую. Если не прошла, продолжает работать старая версия.

### Ошибка сборки

При неудачной сборке Coolify отправляет учителю уведомление в Telegram с именем проекта. Учитель открывает лог в панели и пересылает ученику текст ошибки.

### Конец курса

Статические сайты остаются на своих поддоменах как портфолио ученика. Бэкенды и боты учитель останавливает, чтобы они не занимали память, и запускает снова по просьбе ученика.

## Инфраструктура

Для 20 одновременных проектов достаточно одного VPS на 2 ядра и 4 ГБ памяти и одного домена с wildcard-записью, чтобы любой поддомен сразу вел на сервер. Coolify занимает около 2 ГБ, Forgejo ещё около 300 МБ, остальное уходит проектам учеников.

### Сервер

- Провайдер: Beget, дата-центр в Санкт-Петербурге, произвольная конфигурация. Автоматические бэкапы раз в несколько дней входят в цену.
- Конфигурация: 2 vCPU, 4 ГБ RAM, от 40 до 60 ГБ NVMe, публичный IPv4.
- Система: Ubuntu 24.04 LTS.
- Вход по SSH только по ключу, вход по паролю и вход под root отключены.
- Фаервол ufw: открыты порты 22, 80 и 443. Порт 8000, на котором Coolify работает после установки, закрывается, когда панель переедет на домен.
- Автоматические обновления безопасности через unattended-upgrades.

### Домен и DNS

Домен в зоне .ru регистрируется на Сергея у REG.RU или RU-CENTER, DNS остаётся у регистратора. Cloudflare не используется, потому что в России соединения с ним замедляются.

| Запись | Тип | Значение | Зачем |
| --- | --- | --- | --- |
| `@` | A | IP сервера | Витрина работ учеников |
| `*` | A | IP сервера | Поддомены учеников и панель `panel.<домен>` |

HTTPS-сертификаты выпускает встроенный в Coolify прокси Traefik через Let's Encrypt, отдельный сертификат на каждый поддомен.

Домен покупается перед пилотом. До этого проекты, панель и Forgejo работают на временных адресах вида `<имя>.<IP сервера>.sslip.io`, которые Coolify выдаёт по умолчанию, по HTTP. Реальные ученики на временные адреса не заводятся, потому что при переезде на домен их ссылки и адреса репозиториев сменятся.

## Платформа деплоя

Сборкой и запуском проектов занимается Coolify, бесплатная версия для установки на свой сервер. Каждый проект ученика работает в отдельном Docker-контейнере.

&#91;embedded content: как код ученика попадает на сервер\]

Ученик отправляет код в Forgejo на том же сервере, Forgejo сообщает об этом Coolify, и Coolify перезапускает контейнер. Посетители сайтов идут через Traefik, а боты сами обращаются к серверам Telegram.

### Установка

1. Установить Coolify официальным скриптом, он сам ставит Docker:

```bash
curl -fsSL https://cdn.coollabs.io/coolify/install.sh | sudo bash
```

2. Создать аккаунт владельца и перенести панель на `panel.<домен>` с HTTPS.
3. В настройках сервера указать wildcard-домен `https://*.<домен>`, чтобы новые приложения получали поддомен автоматически.
4. Отключить автообновление Coolify, обновлять вручную после снапшота.

### Хранение кода: Forgejo

Репозитории хранятся в Forgejo на том же сервере, потому что GitHub не даёт аккаунты детям младше 13 лет. Forgejo похож на GitHub по интерфейсу, но аккаунты в нём заводит учитель, и данные учеников не уходят на чужие серверы.

1. Развернуть Forgejo как сервис в Coolify на адресе `git.<домен>`.
2. Отключить свободную регистрацию, аккаунты создаёт только учитель. Логин ученика совпадает с его поддоменом и не содержит фамилии.
3. Создать организацию школы, все репозитории учеников и шаблоны живут в ней.
4. Завести служебный аккаунт \`coolify-reader\` с правом чтения всех репозиториев организации и одним SSH-ключом, который хранится в Coolify. Тогда для нового проекта не нужно добавлять ключи, сборку по пушу запускает вебхук. Forgejo отправляет вебхуки в формате Gitea, их поддержку в Coolify нужно проверить на этапе 3. Если они не сработают, сборку запускает вебхук на Deploy-URL из API Coolify.
5. Вебхук учитель настраивает сам при создании проекта. Это первый кандидат на автоматизацию через ИИ-ассистента или скрипт.

### Уведомления

- Подключить уведомления Coolify в Telegram-чат учителя.
- События: сборка упала, контейнер остановился, диск заполнен больше чем на 80%, бэкап не сделан.

## Шаблоны проектов

Для каждого типа проекта делается шаблонный репозиторий (template-репозиторий в Forgejo), который собирается в Coolify без доработки. Ученик меняет код внутри готовой структуры и не думает о сборке.

| Шаблон | Что внутри | Как собирается | Адрес |
| --- | --- | --- | --- |
| `template-static` | `index.html`, папки `css`, `js`, `img` | Static, раздаётся как есть | `имя.<домен>` |
| `template-python-web` | Flask, `app.py`, `requirements.txt`, порт 8000 | Nixpacks определяет Python сам | `имя.<домен>` |
| `template-node-web` | Express, `package.json` со скриптом `start`, порт 3000 | Nixpacks определяет Node сам | `имя.<домен>` |
| `template-tg-bot` | aiogram 3, `bot.py`, `requirements.txt`, токен из `BOT_TOKEN`, режим polling | Nixpacks, запуск без входящего порта | Не нужен |

В каждом шаблоне есть:

- `README.md` на русском с тремя шагами: изменить код, сделать коммит, нажать Sync в VS Code;
- `.gitignore`, в котором уже есть `.env`, чтобы токены не попадали в репозиторий;
- страница или команда `/start`, которая работает сразу после первого деплоя.

Боты, которым нужно хранить данные, используют SQLite в папке `/data`, которая подключается к контейнеру как постоянный том. Без тома данные пропадают при каждом деплое.

### Витрина работ

На главном домене живёт статическая страница со списком работ учеников. Она собирается из репозитория `showcase`, в котором лежит файл `works.json` с записями вида "ник, название работы, ссылка, тип, дата".

- Учитель сам решает, какая работа попадает на витрину, автоматически туда ничего не добавляется.
- Для ботов в карточке стоит ссылка вида `t.me/<имя_бота>`.
- В карточках только ники, без имён, фамилий и фото.
- После внедрения ИИ-ассистента работу можно добавить на витрину сообщением боту, бот сам делает коммит в `works.json`.

## Безопасность и лимиты

Один проект ученика не должен занять весь сервер или добраться до чужих данных. Для этого у каждого контейнера свои лимиты, а секреты хранятся только в панели.

### Лимиты на один проект

| Тип проекта | CPU | Память |
| --- | --- | --- |
| Статический сайт | 0,25 ядра | 64 МБ |
| Сайт с бэкендом | 0,5 ядра | 256 МБ |
| Telegram-бот | 0,25 ядра | 256 МБ |

На тестовом стенде бот на aiogram при запуске не уложился в 128 МБ и падал по нехватке памяти, а после запуска занимает около 160 МБ, поэтому его лимит 256 МБ. Coolify с Forgejo занимают около 1,8 ГБ, так что на сервере с 4 ГБ помещается примерно 12 ботов и бэкендов вместе, статики заметно больше. Для 20 проектов с ботами нужен сервер на 8 ГБ или отдельный сервер для ботов.

### Правила

- У учеников нет доступа к панели и к SSH.
- Токены ботов и пароли хранятся в переменных окружения Coolify. Если токен попал в репозиторий, учитель отзывает его в @BotFather и вписывает новый.
- На сайтах нет настоящих фамилий, фото учеников и форм, которые сохраняют личные данные посетителей. Иначе действует 152-ФЗ, а для несовершеннолетних нужно письменное согласие родителей.
- Поддомены называются по нику или названию проекта, а не по фамилии.
- Учитель время от времени просматривает опубликованные проекты, потому что за содержимое сайтов на домене отвечает его владелец.

## Бэкапы и обновления

Код учеников теперь хранится в Forgejo на нашем сервере, поэтому потеря сервера без бэкапа означает потерю всех работ. Бэкап Forgejo должен лежать вне сервера, одних снапшотов мало.

| Что | Как | Как часто | Хранится |
| --- | --- | --- | --- |
| Весь сервер | Автоматические бэкапы Beget (на деле раз в несколько дней) | Раз в сутки | 7 последних |
| Репозитории и база Forgejo | `forgejo dump` по расписанию, архив уходит в S3 у провайдера | Раз в сутки | 30 дней |
| База настроек Coolify | Встроенный бэкап Coolify в S3 | Раз в сутки | 14 дней |
| Данные ботов (`/data`) | Входят в снапшот сервера | Раз в сутки | 7 последних |

Правила обновлений:

1. Перед обновлением Coolify администратор делает ручной снапшот.
2. Новую версию ставит не раньше чем через неделю после выхода, примерно раз в месяц.
3. После обновления проверяет, что один сайт и один бот собираются и работают.

Раз в квартал администратор пробует восстановить сервер из снапшота на временной машине, чтобы убедиться, что бэкапы рабочие.

## Слой подключения и проверки проектов

Между Forgejo и Coolify стоит небольшой сервис, мастер подключения. Он приводит любой проект к единому контракту, проверяет каждый пуш и только после этого запускает сборку в Coolify. Учитель и ученик не видят настроек сборки, доменов, ключей и вебхуков.

### Контракт проекта

В корне репозитория лежит файл `school.toml`, который описывает проект. Все настройки Coolify мастер выводит из этого файла.

```toml
type = "telegram-bot"      # static | python-web | node-web | telegram-bot
entry = "bot.py"           # файл запуска
requirements = "requirements.txt"
python = "3.12"
secrets = ["BOT_TOKEN"]    # значения хранятся только в Coolify
data_dir = "data"          # папка, которая переживает пересборку
```

Шаблоны уже содержат контракт, поэтому проект ученика из шаблона подключается без вопросов.

### Подключение внешнего проекта

Учитель вставляет ссылку на репозиторий, а дальше отвечает только на вопросы, если они возникли.

1. Мастер импортирует репозиторий с GitHub в организацию school в Forgejo.
2. Мастер разбирает код правилами:
   - тип проекта по библиотекам (aiogram, python-telegram-bot, pyTelegramBotAPI, Flask, FastAPI);
   - файл запуска по `start_polling`, `run_polling`, `app.run` и `if __name__ == "__main__"`;
   - `requirements.txt` в любой папке, а если его нет, список зависимостей по импортам;
   - имена переменных окружения по `os.getenv` и `os.environ`;
   - запись в файлы и SQLite, чтобы подключить постоянную папку.
3. Если что-то неоднозначно, мастер задаёт вопрос с готовыми вариантами, например "Какой файл запускать: bot.py или main.py?".
4. Мастер добавляет `school.toml` и недостающие файлы отдельным коммитом "Подготовка к запуску". Код автора он не меняет.
5. Мастер спрашивает значения секретов из контракта и проверяет токен бота запросом `getMe`. Тут же он проверяет и при необходимости снимает старый webhook бота.
6. Мастер создаёт приложение в Coolify через API с лимитами и постоянной папкой и ставит вебхук в Forgejo.
7. Мастер запускает первую сборку и проверяет, что процесс работает дольше минуты без падений. Результат приходит учителю одним сообщением.

### Проверки на каждом пуше

Вебхук Forgejo идёт в мастер, а не напрямую в Coolify. Если проверка не пройдена, старая версия продолжает работать, а ученик и учитель получают объяснение.

| Проверка | Что ищет | Результат |
| --- | --- | --- |
| Токен в коде | Строки вида `123456789:AA...` и другие ключи | Блокирует деплой, просит сделать `/revoke` |
| Размер | Файлы больше 20 МБ, репозиторий больше 200 МБ | Блокирует |
| Контракт | Файл запуска существует, зависимости соответствуют импортам | Блокирует, предлагает исправление |
| Запрещённое | Майнеры (xmrig, `stratum+tcp`, адреса пулов), сканеры сети, запуск скачанных бинарников | Блокирует, разблокировать может только учитель |
| ИИ-ревью изменений | Подозрительное поведение, которое не ловят правила | Помечает и пишет учителю, сам не разрешает |

### Контроль во время работы

Проверки кода можно обойти, например скачав майнер уже после запуска, поэтому мастер следит и за работающими проектами.

- Лимиты CPU и памяти на каждый контейнер уже есть, один проект не может занять весь сервер.
- Если проект дольше 10 минут упирается в свой лимит CPU, мастер останавливает его и пишет учителю. У учебного бота такой нагрузки не бывает, а у майнера она постоянная.
- Исходящие подключения к известным пулам майнинга блокируются фаерволом на уровне Docker.
- Размер репозиториев ограничен квотами Forgejo, а размер постоянных папок мастер проверяет раз в час.

### Роль нейросети

Мастер работает и без нейросети, потому что основная работа делается правилами. Модель добавляется для того, что правилами не покрыть:

- разобрать неоднозначный проект и предложить черновик `school.toml`;
- объяснить ошибку сборки простыми словами;
- просмотреть изменения и пометить подозрительное для учителя.

Модель может только предложить или пометить, но не разрешить то, что запретили правила. Код ученика может содержать текст, который пытается уговорить модель пропустить проект, поэтому окончательное решение о блокировке принимают правила и учитель. ИИ-ассистент из следующего раздела работает поверх мастера и даёт учителю чат вместо формы.

### Реализация

- Сервис на Python (FastAPI), развёрнут в том же Coolify, работает через API Forgejo и Coolify.
- Интерфейс для учителя: страница мастера на `deploy.<домен>` со списком проектов, статусами и кнопкой "Подключить проект". Панель Coolify учителю нужна только в нестандартных случаях.
- Поддерживаемые типы и сборщики описаны в таблице ниже. Сборку везде делает Coolify, мастер только задаёт папку, команду запуска, порт и домен.

| Тип | Как распознаётся | Запуск | Адрес | Память на стенде |
| --- | --- | --- | --- | --- |
| Статический сайт | `index.html` вне папок templates, public, static | Сборщик Static | Поддомен | 3 МБ |
| Сайт на Python | Flask, FastAPI, Django в импортах | `flask run` или `uvicorn` на 0.0.0.0:8000 | Поддомен | 21 МБ (Flask) |
| Telegram-бот на Python | aiogram, python-telegram-bot, pyTelegramBotAPI | `python <файл>` | Нет | 150 МБ (aiogram) |
| Python-программа | `if __name__ == "__main__"` | `python <файл>` | Нет | не проверялось |
| Сайт на Node.js | express, fastify, koa, next, hono в package.json | `npm start` или `node <файл>`, порт через PORT | Поддомен | 27 МБ (Express) |
| Telegram-бот на Node.js | telegraf, grammy, node-telegram-bot-api | `npm start` или `node <файл>` | Нет | не измерялось |

Если в репозитории есть и Python, и Node.js, мастер спрашивает, что запускать. Для FastAPI он сам добавляет uvicorn в зависимости, для Django предупреждает про ALLOWED\_HOSTS. После сборки сайта мастер открывает его адрес и помечает проект, если страница не открывается.

По замерам сайты занимают от 5 до 50 раз меньше памяти, чем бот на aiogram, поэтому оценка "12 проектов на 4 ГБ" справедлива только для ботов. При смешанных проектах 20 работ помещаются с запасом.

Известные ограничения:

- сайты на Next.js и другие проекты со сборкой не проверялись;
- пока мастер перезапускается при обновлении (около минуты), вебхуки от Forgejo теряются, и такой коммит нужно пересобрать кнопкой;
- постоянная папка для данных не подключается ни для одного типа.

## ИИ-ассистент для рутинных задач

Ассистент нужен, чтобы ни одной роли не приходилось открывать консоль для повседневной работы. Для учителя и администратора он входит в систему, для ученика включается по желанию.

| Роль | Что делает ассистент | Как подключён | Обязателен |
| --- | --- | --- | --- |
| Администратор | Настраивает сервер, разбирает сбои, делает обновления | Claude Code по SSH из Еревана или открытый агент (OpenCode) с моделью, доступной из России | Да |
| Учитель | Заводит проект ученика по сообщению в чате, показывает и объясняет логи, перезапускает проекты, сообщает о сбоях | Telegram-бот учителя, который работает через API Coolify | Да |
| Ученик | Объясняет ошибку сборки простыми словами, отвечает на вопросы по своему проекту | Тот же бот с урезанными правами, учитель включает его для каждого ученика отдельно | Нет, опция |

### Права ассистента

Бот работает только через API Coolify и не имеет доступа к SSH, поэтому он может делать только то, что разрешено в его коде. Список разрешённых вызовов API задаётся явно, модель не может его расширить.

- Без подтверждения: читать статусы и логи, перезапускать и пересобирать проект.
- После нажатия кнопки "Подтвердить" в Telegram: создать проект, изменить переменные окружения, остановить проект.
- Никогда: удалять проекты и серверы, менять настройки самого Coolify. Это делает администратор в панели.
- Ученик через бота видит и перезапускает только свой проект.
- Каждое действие записывается в журнал с автором запроса и временем.

### Данные и модель

- Перед отправкой в модель бот вырезает из логов токены и пароли, например строки вида `123456:ABC...` и значения переменных окружения.
- Имена и контакты учеников в модель не отправляются.
- Модель должна быть доступна и оплачиваться из России. Подходят YandexGPT через Yandex AI Studio и GigaChat API.

Ассистент внедряется после пилота, когда базовая схема уже работает без него. Так при первых сбоях будет понятно, что сломалось, сервер или ассистент.

## Этапы и критерии приёмки

Работа идёт по порядку, и следующий этап начинается, когда выполнен критерий предыдущего. Этап 5 идёт сразу после аренды сервера и занимает 48 часов параллельно с остальными, потому что от него зависит выбор страны сервера.

| # | Этап | Готово, когда |
| --- | --- | --- |
| 1 | Аренда VPS на месяц и базовая защита сервера | Вход по SSH работает только по ключу, фаервол включён |
| 2 | Установка и настройка Coolify | Панель открывается на `panel.<домен>` (до покупки домена на адресе sslip.io), порт 8000 снаружи закрыт |
| 3 | Forgejo, организация школы и связка с Coolify | Пуш в тестовый репозиторий обновляет сайт меньше чем за 3 минуты |
| 4 | Шаблоны репозиториев | Каждый шаблон собирается и работает без правок |
| 5 | Проверка Telegram с сервера | Тестовый бот отвечает 48 часов без обрывов. Если нет, боты уезжают на второй сервер в Казахстане или Армении, подключённый к той же панели |
| 6 | Бэкапы и уведомления | Есть хотя бы один снапшот, упавшая тестовая сборка присылает уведомление в Telegram |
| 7 | Инструкции для учителя и ученика | Учитель сам, без помощи, заводит нового ученика за 5 минут |
| 8 | Покупка домена, DNS-записи и переезд адресов с sslip.io на домен, затем пилот на 2 или 3 учениках | Все сервисы открываются на домене по HTTPS, ученики неделю обновляют проекты сами, без участия администратора |

Этап 9, ИИ-ассистент, идёт после пилота. Он готов, когда учитель заводит нового ученика и разбирает упавшую сборку только через чат с ботом, не открывая панель.

## Бюджет

Ориентир по бюджету около 2000 ₽ в месяц, при необходимости его можно увеличить, а один сервер нужной конфигурации в 2026 году стоит около 1950 ₽ и занимает почти весь лимит. ИИ-ассистент и второй сервер для ботов выходят за лимит. Цифры приблизительные, их нужно сверить с тарифами провайдера на момент покупки.

| Статья | Цена |
| --- | --- |
| VPS 2 vCPU, 4 ГБ | около 1950 ₽ в месяц у Beget (40 ГБ NVMe, IPv4 включён) |
| Снапшоты и S3 для бэкапов | бэкапы Beget бесплатно, цену S3 для архивов Forgejo нужно уточнить |
| Домен .ru | 200 до 900 ₽ в год |
| Coolify, Forgejo, Let's Encrypt | 0 ₽ |
| Второй VPS для ботов, если понадобится | ещё около 1300 ₽ в месяц (2 ядра, 2 ГБ) |

ИИ-ассистент добавит примерно от 200 до 1000 ₽ в месяц за запросы к модели, сумма зависит от модели и от того, включён ли он для учеников. Бот работает на том же сервере и отдельного VPS не требует.
